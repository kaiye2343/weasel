# 皮肤资源发布与应用容器读取

本轮针对 [SearchHost 图片访问拒绝现场](SEARCH-SKIN-ACCESS-20261022.md)，不代表其他历史图片故障、长串输入延迟或“问题1”均已解决。

## 资源与权限

- 算法服务在外观加载／刷新时调用共用原生发布器。设置中心沿用原有选择与刷新流程，不实现第二套缓存，不修改皮肤包格式或 UIStyle 序列化。
- 默认缓存为 Windows 真实 LocalAppData 下的 `Rime\SkinAssets\v1`；Known Folder 查询使用 `KF_FLAG_NO_PACKAGE_REDIRECTION`，不从开发工具、当前工作目录或旧链接推导。私有维护记录位于同级 `Rime\SkinAssetState\v1`。
- 仅发布有效样式使用的图片。九宫格优先于旧背景，未使用的旧背景路径不发送给客户端；装饰、框体及旧背景复用同一发布入口。
- 发布文件名为内容 SHA256 加已允许的图片扩展名。沿用生产 GDI+ 解码器，单图不超过2048×2048，源文件总量不超过100MiB，实际发布图片解码总量不超过64MiB。
- 普通及受限应用容器对最终图片只读、对缓存目录只读及遍历；当前用户、SYSTEM、管理员管理缓存。新建公共祖先目录只给予不继承的遍历权限，防止未来的无关资料文件继承图片读取授权。既有资料父目录权限保持。
- 皮肤包、配置、日志、用户词典和维护记录不发布。缓存图片属于可供本机应用读取的展示资源。拒绝受控目录重解析点及路径越界；不用链接指回私人源文件。

## 生命周期与回退

1. 独占维护锁下，在私有 staging 写入、刷新、核对摘要和真实解码预算，设置受控 ACL 后同卷原子发布。相同内容复用目标，损坏缓存使用验证副本替换。
2. 服务启动、新会话和外观刷新只向客户端传已发布路径。新会话尚未取得方案状态时先使用无图安全样式，失败不会带出私人路径。
3. 多会话刷新经过共用事务接缝，全部准备成功后才提交；失败保留旧样式并返回错误，设置中心沿用选择状态回滚。无可用旧外观时保持可输入的原生文字框。
4. 普通按键、换页和高亮路径不调用发布器。样式路径摘要改变才使现有图片缓存失效；`runtime.json` 提供累计 `skinAssetHashReads`，用于区分会话／样式加载与逐键重复发布。
5. 仅启动与成功刷新后维护缓存。保护全部会话引用和最近两组成功引用；其余资源在修改时间及最后访问／显式引用时间均满30天后才可删除。引用只更新访问时间，不改变渲染缓存使用的修改时间。坏维护记录停止清理，占用文件跳过，不递归清理未知目录。

## 诊断与自动验证

- 根据相关进程包标识发现其 AC、LocalCache、LocalState 日志候选位置，不写死搜索包名称。并行保留普通桌面日志，来源索引避免同名日志覆盖。
- 只复制严格匹配 PID 的 render／presentation 日志及轮转，单份最多512KiB、总计最多64份；拒绝链接日志。渲染日志可记录已发布图片摘要，不记录输入正文或源图片完整路径。
- 独立 C++ 测试覆盖发布、摘要复用、失效修复、无图片、失败不改输出、并发锁、恶意路径及30天保留。服务事务测试调用真实发布器，验证第二会话失败不提交、旧成功结果保留与纯色样式。
- 真实 AppContainer 与 LPAC 子进程调用生产解码器：私人图片读取被拒绝、发布图像像素及 Alpha 一致、不能写入／删除／创建缓存或修改权限；共同父目录下新建的模拟私人词典也保持不可读。测试不创建窗口或发送输入。
- 原生预览的 `--publication-test` 无窗口入口验证真实 UIStyle 路径替换、框体／旧背景及布局不变、失败原子性；既有 DPI、布局、命中、缓存与负控制门槛继续保留。
- 托管回归验证日志包目录计算、来源去重、同名文件及大小限制。完整 Actions 同时构建 x86／x64、设置中心、预览和安装包，产物生成 SHA256 清单。
