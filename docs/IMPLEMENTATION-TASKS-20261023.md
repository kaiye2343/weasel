## 分工和执行规则

- Codex：查阅实际代码、确定接口和精确修改方案；完成网页及设置中心前端；指导、审查 DSH 的实际 diff，运行验证，管理 Git 和 Actions。
- DSH：按单次任务合同完成非前端的小批次实现；未知接口、歧义或权限失败立即提出 QUESTION／BLOCKED 并退出，等待指导。
- 各批次独立限定可写文件。存在文件交叉时串行执行；不得为了并发拆出重复架构。
- DSH 不提交、推送、安装依赖、运行日常服务、修改真实用户数据、修改 AGENTS 或再次委派。产物必须由 Codex 验收。
- 已确认路由顺序：WorkBuddy Global 的 `deepseek-v4.1-flash` → 同提供方 `deepseek-v4.1-flash-sg` → 已授权的 DeepSeek 账号 Flash。重复 429 才切换，不将认证或权限故障当作 429。
- 保持 `workspace-write / ask`。单次任务运行记录位于忽略目录；不得将凭据、模型输出或私人诊断提交到 Git。
- 每批通过后进行功能提交；推送到 fork 已获授权。完整 CI 失败时先修复该批，不继续叠加依赖它的新功能。
- 图形自动回归由隔离 CI 执行，日常桌面操作由用户完成。安装与真实账号连接仍需单独授权。

## 每批审查合同

1. 派发前记录基线、允许文件、生产符号、实现步骤、停止条件及预期测试。
2. 收回后核对文件范围；审查真实 diff，检查未知符号、协议兼容、资源释放、并发与失败行为。
3. 使用 CodeGraph 查询调用者和影响范围；索引不替代源码和编译。索引过期时读取该文件的最新内容。
4. 运行能在本机完成的无窗口测试、静态检查；本机缺工具链时明确记录，交由完整 Actions 验证。
5. 测试失败回到原批次指导修正；不以 DSH 的 DONE 标签作为完成证据。
6. 只添加本批明确文件到 Git，检查暂存 diff；提交说明不含工具署名。保留用户未提交修改。
