## 2. 阶段 A：构建质量

### A1. 隔离负控制、正式构建和打包

主要入口：`.github/workflows/commit-ci.yml`、`tools/test-native-regressions.ps1`、原生项目 `.vcxproj`。

当前负控制脚本会把历史源码写回工作区，重建 `WeaselUI` 和预览，然后恢复当前源码。改为以下结构：

1. 正式源码工作区只读用于编译，不在其中应用旧算法或故障注入。
2. 每个负控制使用当前提交的独立临时源码副本，只在副本里替换指定旧实现或注入错误。
3. 控制目录位于本次构建拥有的临时根内。不得复制私人 `.tools`、个人资料或用户未提交文件；以 Git 中当前提交的源文件清单创建副本。
4. 第三方 SDK 可以从已校验的依赖缓存复制或使用明确的只读绝对路径。不可复用正式构建的对象文件、静态库或 PDB。
5. 每组控制拥有独立 `IntDir`、`OutDir`、编译器 PDB、链接器 PDB、日志和临时配置。目录至少区分控制名、Configuration、Platform、ProjectName。
6. 保留现有负控制的精确预期退出码与故障特征检查，避免“随便失败一次”也算通过。
7. 正式 x86／x64 组件从当前源码干净构建；正向测试使用同一批正式产物。打包阶段不再运行可能替换生产源码或重建共享库的控制测试。
8. 安装包来源使用明确清单，排除负控制、诊断夹具和旧输出；安装包内组件与正式输出逐项核对。
9. 保留失败控制日志供分析。清理只允许本次创建、解析后位于测试根内的路径，禁止递归清理用户目录或链接目标。

工作流拆出清晰步骤：独立测试 → 正式编译 → 正式产物验证 → 打包 → 校验与上传。保留现有完整门槛，不为了减少耗时跳过负控制或真实容器测试。

### A2. 调试符号

- 正式 Release 使用非增量链接，保留完整调试信息；不删除 PDB、不禁用 `LNK4020`。
- 明确设置对象和编译器 PDB 的项目专属目录；可执行文件／DLL 对应 PDB 输出到该架构的正式输出目录。静态库携带的调试信息必须与最终链接使用的对象一致。
- 在 Windows runner 使用随 Visual Studio 提供的 DIA 接口加载符号。新增小型命令行验证工具，输入最终二进制和对应 PDB，输出结构化结果及非零失败退出码。
- 验证二进制中的 CodeView 标识与 PDB GUID／age 匹配；通过 DIA 枚举关键模块的编译单元、函数、源码行及非空类型记录。至少覆盖服务、前端 DLL、部署器及预览。
- DIA 不可用、符号缺失或解析失败必须报告为检查失败，不能自动退化为“文件存在即可”。
- 首先用现有日志和构建参数建立复现，再验证隔离后的结果；若仍出现损坏，保留失败 binlog／PDB并继续缩小构建组合，不宣称隔离已证明根因。
- 要求连续两次独立干净 CI 通过；这是验证构建稳定性的门槛，不是要求安装两次。

### A3. 警告对应修正

| 警告／入口 | 规定修正 | 关键测试 |
|---|---|---|
| `HWND → int`，`WeaselIPCServer/WeaselServerImpl.cpp::Start` | 保持 `int` 接口，窗口创建成功返回 1，失败或已存在实例保持 0；核对全部调用方只使用成功状态 | 成功、创建失败、重复实例；x64 不截断句柄 |
| `size_t → DWORD`，`WeaselIPC/PipeChannel.cpp` | 在调用 Windows API 前做受检转换，越界使用现有 DWORD 错误传播机制；固定大小常量用静态断言 | DWORD 上界及上界+1；失败不发送残缺消息 |
| 候选下标等缩窄，`WeaselClientImpl` | 大于协议字段范围返回失败，不发送；协议内索引仍由服务校验 | 普通索引、越界、非活动会话 |
| `LRESULT` 与 session／HRESULT 转换 | 核对现有管道响应实际类型；按明确的无符号编号或 HRESULT 位模式处理，禁止统一按“负值错误”解释 | 高位为1的合法32位值、失败值、x86／x64一致 |

| PIDL限定符，`DictManagementDialog.cpp` | 使用正确 PIDL 类型和拥有者，检查创建失败；COM只有初始化成功时配对释放 | COM已是其他模型、PIDL创建失败、成功释放 |
| `localtime`，`include/WeaselUtility.h` | 使用 `localtime_s`，保持正常日志格式；失败返回明确不可用时间标记，不解引用无效结果 | 并发调用、格式、失败夹具 |
| 摘要名 `wchar_t → char` | 只在已验证ASCII摘要字符的局部路径显式转换；非法字符拒绝 | 合法摘要、非ASCII、错误扩展名 |
| 未用异常变量 | 不需要内容时去掉变量名；需要错误时纳入现有非敏感诊断 | 异常路径仍有明确结果 |

不要用全局强制转换、关闭编译器警告或修改 IPC 字段大小代替正确修复。边界测试使用小型夹具，不实际分配超过4GiB的内存，也不改写系统注册表。

## 4. 阶段 C：性能诊断与缓存

### C1. 测量边界和数据格式

主要入口：`RimeWithWeasel/RimeWithWeasel.cpp`、`WeaselIPC/WeaselClientImpl.cpp`、`WeaselUI/WeaselPanel.cpp`、`WeaselSkinPreview/Preview.cpp`。

新增可复用的本体性能探针，使用 QueryPerformanceCounter／等价单调时钟。默认关闭；隔离命令行测试显式开启，可指定持续时间，默认30秒、最大120秒。不要通过修改用户永久配置或给日常进程注入代码来开启。

定义以下阶段，保持名字稳定，供对照脚本使用：

| 名称 | 范围 | 解释 |
|---|---|---|
| `core_process_key` | Rime处理按键调用 | 核心成本，只测量不优化核心 |
| `context_response` | 读取候选和构造响应 | 服务端本体成本 |
| `ipc_roundtrip` | 客户端请求到收到响应 | 含服务处理，不能与核心时间直接相加 |
| `layout` | 字体测量及候选布局 | 不含资源IO |
| `resource_prepare` | 解码、缩放及资源缓存准备 | 冷启动与热缓存分别统计 |
| `paint_submit` | 组帧及交给呈现接口 | 不等于屏幕真正显示时间 |
| `present_complete` | 有可靠完成信号时的呈现完成 | 不可测时输出 unavailable，禁止伪造为提交时间 |

每份报告包含 schemaVersion、源码号、PID、位宽、后端、DPI、场景编号、采样时长、各阶段样本量/P50/P95/max，以及文件属性查询、摘要读取、解码、缩放、背景重建、提交帧、丢弃样本计数。

- 不保存原始输入、候选、个人路径或词典内容。场景编号仅标识测试夹具。
- 计时数据在内存聚合；每阶段最多保留65536个样本，达到上限停止该阶段采样并报告截断，不无限增长。结束时统一写报告，不逐键写日志。
- 探针关闭时不查询文件、不加全局互斥锁、不分配样本；只允许廉价的关闭状态分支。
- 本阶段不修改 IPC 消息布局或 UIStyle。独立端点结果按测试场景对照，不尝试用不可靠时间推导逐键跨进程关联。
- 增加启用／关闭探针对照，证实采样开销；明显影响结果时先修探针，再使用其数据作优化依据。

### C2. 固定资源查询和发布去重

1. 审查 `WeaselPanel` 当前 `last_write_time` 调用及资源刷新入口，记录热路径计数作为基线。
2. 对服务发布的、位于真实受控缓存根且通过发布验证的内容摘要路径，正常帧以样式身份和资源代次复用解码资源，不逐帧查文件。
3. 不以“文件名看起来像SHA256”认定任意路径可信。原生预览直接读取源图片时保留源更新检测，且只在显式刷新／有限频率检查中执行。
4. 显式刷新、隐藏重显时的必要校验及加载失败恢复不得被永久缓存早退吞掉。旧缓存成功后丢失磁盘文件，可以继续绘制内存图；下一次受控刷新报告并重新发布／加载。
5. 同一外观事务对重复资源按规范化源路径去重，输出顺序与原图层对应不变；重复引用仍返回对应的发布路径。
6. 不引入仅依据mtime跨事务跳过内容摘要的捷径。覆盖同版本皮肤且内容改变必须生成新摘要路径。

### C3. 缓存拥有者与失效规则

- 审查静态阴影位图指针，改为与窗口／绘制实例寿命绑定的RAII资源；有意共享的只读图像采用明确共享所有权。
- 缓存分为源图解码、目标尺寸缩放、固定背景／装饰合成三个层次，避免按键事件使全部缓存同时失效。
- 失效键至少包含所依赖的有效样式、图像身份、像素尺寸、DPI和设备代次；固定背景还包含颜色、圆角、阴影、九宫格参数和注音框高。
- 高亮、鼠标悬停、选词序号改变只重绘必要动态内容。框高收起、DPI或候选宽度变化必须重算相应布局和图像锚点。
- 资源准备在临时拥有者中完成，成功才替换；失败继续持有旧有效资源，不能交付一半新图像一半旧布局。
- 销毁窗口、换设备、切变体和异常退出均释放对应缓存；保留既有活动图像解码预算，新增GPU资源也要计入独立受控预算，不能无限累积变体。

### C4. 性能验收

- 数据集：短／长候选、16/32/64/128字母合成输入、纯色与PNG、上方／旁边／隐藏注音、固定／变动尺寸、96/144/192 DPI、冷／热缓存。
- 本体绘制比较使用同一候选数据、图片、字体和编译参数；算法测试继续使用相同官方核心。不能把不同机器的核心和前端耗时相加。
- ABBA顺序至少三组。保存每轮数据，不只展示最快一轮；对输出候选、注音、几何和像素语义做一致性检查。
- 热缓存连续1000次高亮／翻页样式稳定操作中，发布和摘要读取增量必须为0；仅高亮变化时，PNG解码、缩放和固定背景重建也为0。
- 建立至少1000次隐藏重显／创建销毁的自动资源压力场景。预热后句柄数不得随迭代持续增长；内存有界且能随实例销毁释放。
- CI检查确定性计数和正确性。计时作为报告，不因共享runner单次抖动设置脆弱的绝对毫秒门槛。
- 本体性能修改只有在目标场景重复表现出收益、且其他场景没有超出基线波动的持续退化时合入；否则只保留有效诊断，撤回无收益的复杂缓存改动。

## 5. 阶段 D：预览一致性

### D1. 复用现有入口

现有实现位于 `designer/app.js`、`designer/geometry.js`、`manager/Shorekeeper.Core/DisplayPreferences.cs`；已经支持原始参数／实际显示偏好和偏好导入。不得重复设计同类入口。

- 将“实际显示偏好”来源明确显示为“内置默认值”或“已导入：文件名”；离线网页没有权限自动读取本机设置，不能暗示已连接输入法。
- 导入失败保留上一次有效偏好、皮肤和选中变体，显示具体格式错误。
- 预览偏好不写入皮肤manifest；导出包不因切换预览模式而改变。
- 设置中心使用未保存参数预览时，继续使用私有临时快照，关闭后清理，不写活动配置。

### D2. 共用夹具和原生事实输出

- 新建版本化JSON测试夹具，仅包含合成候选、注音、有效皮肤样式、偏好、图层几何与DPI，无真实词库。
- 浏览器自动化和原生预览测试读取相同夹具；原生增加无窗口布局JSON导出入口，输出内容框、候选矩形、基线、可见框体、装饰矩形、完整画布及原点偏移。
- 固定文字测量值的几何测试要求计算结果一致，映射到设备像素时允许最多1个物理像素的取整差；真实字体测量分别记录差异，不要求浏览器和DirectWrite字形逐像素相同。
- 布局验收重点：候选基线一致、部分缺注音留空、整页无注音按偏好收起、图片相对可见框体锚点稳定、透明画布原点不改变图片语义。
- 网页继续负责皮肤的相对布局；屏幕光标矩形、上下换边、多屏边缘由已有原生位置预览和自动几何测试负责。
- 原生命中区域只包含候选，不因装饰画布扩大而扩大；预览缩放、DPI和原点平移必须在命中换算中一致使用。

### D3. 覆盖矩阵

至少包含旧1.0包、现有1.1包、无皮肤、纯色、多变体、九宫格、左右／上下外扩图片、负坐标图层、仅无注音能力皮肤，以及紧凑／标准／跟随皮肤密度。

对每组运行短候选、长候选、部分无注音、全部无注音与位置切换。图片宽高比、文字遮挡及多字候选不得仅凭截图目测判定，通过矩形关系和实际像素探针辅助验证。

## 6. 阶段 E：实验 D2D／DirectComposition

### E1. 实施策略

- 先读取现有 `codex/dcomp-skin-migration` 分支的代码和记录，明确已完成的是呈现基线还是完整绘制。复用已验证工作，禁止从头生成另一套不兼容后端。
- 先建立内部渲染后端边界，共用布局、候选命中、资源发布和输入处理；不要复制第二份方案／候选业务逻辑。
- 迁移分两步：先验证现有CPU合成帧经DComp呈现和回退，再逐步把背景、位图、文字、阴影转入D2D。第一步不得冒称已经是完整D2D绘制或已降低CPU合成成本。
- 目标支持：预乘Alpha、框内外图层、负／非负z顺序、九宫格、圆角／阴影、分隔线、注音双布局、DPI、窗口定位和命中。
- 默认先尝试硬件设备，失败尝试WARP，二者均失败则回退GDI。诊断和基准必须记录实际设备路径，不能把WARP称为GPU加速。

### E2. 显示偏好与接口

`display.json` 保持 `schemaVersion=2`，新增可选字段：

```json
{"renderBackend":"gdi"}
```

- 合法值仅 `gdi`、`dcomp`，省略为 `gdi`；v1读取转换后也是 `gdi`。未知值校验失败，保留旧有效设置。
- 托管模型新增对应属性；原生使用独立的本地渲染偏好类型；设计器允许导入该字段但不据此模拟GPU，不写进皮肤包。
- 设置中心增加“实验渲染后端”选择及实际回退提示，仍是中性界面。保存继续走备份／原值保存与失败回滚流程，不部署Rime。
- **后端选择由服务读取私人偏好并提供给客户端，不能让AppContainer重新直接读取私人display.json。**
- 为此在现有控制命令枚举增加一个只读查询命令，使用现有DWORD请求／响应传输，返回0代表GDI、1代表DComp；未知旧服务返回0按GDI处理。实施时根据当前枚举分配未占用ID，不改变已有ID、消息结构或UIStyle归档。
- 客户端仅在创建会话、收到既有外观失效／重载通知和窗口重建时查询，不逐键查询。不靠修改UIStyle无关字段强行触发刷新；如现有重载传播不能覆盖无样式变化情况，应扩展现有控制刷新处理，保证每个已连接客户端在下一次显示前重新查询。
- 成套构建服务、前端与部署器。旧客户端忽略新能力，新客户端对旧服务默认GDI。

### E3. 回退语义

必须区分两类失败，避免向用户承诺当前控制链不能保证的全局客户端事务：

1. **配置无效或服务刷新失败：** 设置中心恢复原文件字节，服务保留原有效外观，返回明确失败。
2. **某宿主设备初始化／呈现失败：** 该宿主回退GDI，保留用户DComp偏好供其他宿主使用；在诊断中分别记录 requestedBackend 和 actualBackend。设置中心显示“部分进程回退”，不宣称所有宿主已经切换成功。

设备丢失后最多尝试一次完整重建；再次失败锁定当前窗口实例的GDI回退。只有显式重新应用后端或创建新窗口实例才允许再试，不逐帧重建。

CPU图像数据和设备位图分离。设备代次变化必须使全部设备对象失效；命中、输入焦点、候选选择和窗口原始光标锚点不随重建丢失。

### E4. 迁移验收

- 原有布局、图片、透明度、注音、位置、容器权限回归分别在两个后端运行。
- 设备创建失败、WARP回退、EndDraw／Present故障、尺寸重建失败使用受控注入验证；仅测试构建可启用故障注入。
- 同一图层和字体下比较输出。固定纯色／位图区域可逐像素检查；文字边缘及阴影按已记录容差检查，禁止用宽松全图均值掩盖图片缺失。
- 比较完整管线的CPU时间、帧提交、可测完成时间、峰值内存和设备重建耗时。不得用不同显示同步策略或单次DrawBitmap速度宣称整体改善。
- 在隔离Windows runner验证完整功能；真实显卡、实际多屏和长时间体验由用户测试，未测试时明确标注。
- 功能或恢复不达标：不在正式设置中心开放该选项，保留实验分支和失败报告。即使通过全部自动门槛，默认仍为GDI。

## 7. 子 agent 工作合同

建议同时最多三个执行者加一个主审，先分界再派发：

| 角色 | 文件／责任边界 | 不得修改 |
|---|---|---|
| A 构建代理 | 工作流、构建属性、隔离测试脚本、符号检查工具 | 生产IPC、UI业务、用户数据 |
| B 原生修正代理 | IPC类型边界、注册清理、时间函数、相应测试 | 工作流、前端、渲染迁移 |
| C 缓存代理 | 阶段A通过后负责探针、缓存、资源生命周期与计数测试 | 设计器前端、librime、安装 |
| 主实现者 | 架构决策、前端、接口整合、审查、提交与交付 | 不跳过其他代理实际diff审核 |

E为后续独立任务，不与C同时修改同一批绘制核心文件。若需要并行，按资源层／呈现层明确文件所有权，交叉文件由主实现者整合。

每次派发必须包含：基线提交、允许文件、禁止行为、接口约定、测试命令、完成条件。代理不得自行提交推送、更新AGENTS、安装依赖或操作日常服务；依赖缺失向主实现者报告。

交回必须提供实际修改文件、接口变化、运行命令与退出码、未验证项、潜在风险。主审通过CodeGraph检查调用者，再读diff、运行测试；不以代理“已完成”自述当作通过。

若使用DSH，读取当前dsh-agent skill，沿用用户已选路由和429回退顺序；不得重新要求已确认的同一选择。前端不交给DSH。
