# 网页设计器与上游渲染评估（2026-10-17）

## 范围与结论

当前维持 GDI+／DirectWrite 两级缓存后端。官方 `upstream/master` 的 DirectComposition／Direct2D 基础可用于继续开发，但**直接替换会丢失当前皮肤能力**。本轮不安装实验版、不迁移日常资料、不修改 Rime 方案或学习数据库。

源码基准为官方 `4aea1978a351e2ce41af20c8fb88a01ce9802de8`。以下为读取实际源码后的判断；性能数据需来自本轮独立基准，不由 API 名称推断。

| 能力 | 官方已有基础 | 当前皮肤所需适配 |
|---|---|---|
| 透明合成 | `d2d.cpp / InitDirect2D` 创建 BGRA8、PREMULTIPLIED 交换链、DComp target/visual；候选窗使用 NOREDIRECTIONBITMAP | 明确透明画布的装饰边界，保留原点平移 |
| PNG 及缓存 | WIC 工厂与状态图标位图缓存 | 移植 PNG 实际路径、解码内存预算、按尺寸／DPI缓存、失败保留旧资源 |
| 框外图片及锚点 | 可画位图，但 `_ResizeWindow` 只按内容框 `GetContentSize` 设置窗口 | 移植 `SkinGeometry` 的 canvas union、`m_skin_origin` 及命中坐标修正 |
| 九宫格 | 不含当前 `skin_frame_image/slice` | 实现九片源／目标矩形、缩小边界与背景裁剪 |
| 图片层顺序 | 原生文字、高亮及图标绘制 | 移植负 z／非负 z 两遍绘制，确保装饰不扩大选词命中区域 |
| 上方／无注音 | 官方有候选注释，但没有本分支上方统一基线与收起行扩展 | 保留 `HorizontalLayout` 测量、分隔线及能力约束 |
| DPI | `InitDpiInfo` 根据窗口／显示器更新字号与布局比例，清理文字格式缓存 | 给图片、背景、canvas union 与命中应用同一比例，跨屏验证 |
| 屏幕边缘 | 官方候选框重定位逻辑 | 用扩展后的完整 canvas 检查工作区，不能只约束文字框 |
| 设备丢失 | OnResize、EndDraw、Present 有重置路径 | 设备相关图片全部失效并重建，保留可重建的 CPU 源数据和现有回退 |

### 性能不能直接推断

- 官方 `DeviceResources::EnsureInitialized` **优先 WARP 软件设备**，失败才试硬件；不能称为默认 GPU 加速。
- `RedrawWindow` 的 `Present(1,0)` 含同步呈现。其耗时与 memcpy、异步提交或单个 DrawBitmap 调用不能直接横比。
- 现有固定底图和缩放图片缓存已经避免逐帧 PNG 解码、缩放。迁移 D2D 后仍须保留这些缓存及失效规则。
- Rime 长句计算与绘制分开。网页设计器和渲染技术迁移不等同于修复算法的长句耗时。

## 可运行验证

`tests/render_backend_benchmark.cpp` 在 Actions 编译执行，**不创建 HWND、不初始化 Rime、不连接服务**。输入为同一 PNG 经现有加载器和缩放器得到的预乘像素；固定底图输入也完全共用。

比较两条路径：

1. GDI 缓存：复制固定底图、动态高亮、缓存装饰图片 1:1 合成。
2. 上游同类 WARP/D2D 技术：上传缓存位图，DrawBitmap／FillRectangle，再通过 staging texture + Map 等待完成并读回 CPU。

覆盖 96／144／192 DPI、带／不带注音框高、600／1800 DIP 内容宽、固定／交替尺寸。每组 5 次预热、40 次采样，CSV 记录提交 P50、完成 P50/P95、与 GDI 像素的平均／最大差异；检查透明边角及不透明框体，并限制平均像素差异。

**限制：这是受控的图片合成微基准，不是完整官方渲染器。** 不包含文字／阴影生成、字体测量、DComp、Present、窗口生命周期、输入事件及 Rime。D2D 的 CPU 回读也不是日常 DComp 呈现路径；结果只能说明对应成本，不能据此宣称日常输入快了多少。完整当前后端仍由原有 `native-performance-test.csv` 单独记录。

迁移门槛：移植上表全部能力，验证透明、设备重建、命中、DPI／边缘后，使用同一候选数据、素材、字号、阴影和呈现条件对比完整后端。没有这些证据前保留当前后端。
