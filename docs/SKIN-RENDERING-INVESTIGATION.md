## 钩子与下一步

1. **内部观察回调有帮助。** 在资源读取、布局完成、帧合成及提交边界记录结果，适合定位、回归和未来扩展；这是本体中的扩展点。
2. **窗口事件钩子用途不同。** [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook) 提供窗口事件通知；`WINEVENT_OUTOFCONTEXT` 不把回调映射进目标进程。它能够支撑跟随窗口，但不会让一个失败的图片读取自动成功。
3. **文件访问观测优先于绘制劫持。** 当前需对照故障进程实际发出的文件请求和返回状态，避免再从外部文件存在推定宿主内的读取必然成功。可先评估 Windows 文件访问跟踪，不立即加入常驻注入钩子。
4. **若证实属于宿主文件访问差异，再考虑集中资源加载。** 由自身服务验证、加载皮肤资源，前端获取受控的只读资源，继续在原生候选窗合成。此为待验证设计，尚未实现，也不等于决定迁移完整独立渲染进程。

## 当前结论

已确定失败发生在图片读取阶段，持续重试未恢复；具体根因仍未确认。暂不宣称修复，不重复重装，也不把外围悬浮窗或全局钩子当作既定替代方案。
