## 钩子与下一步

1. **内部观察回调有帮助。** 在资源读取、布局完成、帧合成及提交边界记录结果，适合定位、回归和未来扩展；这是本体中的扩展点。
2. **窗口事件钩子用途不同。** [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook) 提供窗口事件通知；`WINEVENT_OUTOFCONTEXT` 不把回调映射进目标进程。它能够支撑跟随窗口，但不会让一个失败的图片读取自动成功。
3. **文件访问观测优先于绘制劫持。** 当前需对照故障进程实际发出的文件请求和返回状态，避免再从外部文件存在推定宿主内的读取必然成功。可先评估 Windows 文件访问跟踪，不立即加入常驻注入钩子。
4. **若证实属于宿主文件访问差异，再考虑集中资源加载。** 由自身服务验证、加载皮肤资源，前端获取受控的只读资源，继续在原生候选窗合成。此为待验证设计，尚未实现，也不等于决定迁移完整独立渲染进程。

### 静态绘制缓存（2026-10-16）

- 源码 `213f30a` 的完整 [Actions 38911882515](https://github.com/kaiye2343/weasel/actions/runs/38911882515) 通过，包含路径视图控制测试。其合成候选基准中，无图片、无阴影的单帧中位数为约 1.8—3.7 ms；有图片、无阴影为约 29.5—32.2 ms；有图片和阴影为约 32—46 ms。原图虽已缓存解码，每帧仍做高质量缩放；底框阴影也重复进行模糊。该数据证明绘制存在可避免的开销，不是用户主观体验的替代。
- 用户要求应用皮肤后缓存固定部分。新增两级进程内缓存：按实际目标尺寸保存预乘 Alpha 图片；按内容框尺寸保存底色、边框、阴影及框内下层装饰。后续逐帧复制底框、直接合成已缩放图片，候选文字、高亮和分隔线仍实时绘制。底框尺寸、DPI、样式、有效图片、图片布局或背景资源修改时失效；不固定角色和位置。
- 缓存是可丢弃的加速数据，不写入用户方案或学习数据库。原图、缩放副本、底框和已加载背景共同计入缓存准入预算，超过 64 MiB 或分配失败时使用有效原图绘制；资源加载失败不冻结半成品。整个窗口大小变化仍可能重建底框，不能假定所有帧均命中缓存。
- 原生回归比较缓存底框与重新绘制的像素哈希，检查高亮仍动态变化、样式切换失效、显示／隐藏和资源失败回退；图片控制测试比较透明、浅色、深色背景及上下层不同采样模式。基准同时记录固定长度和交替长度，避免仅报告缓存命中的理想情形。
- 首轮 `5070bbc` 的图片像素测试通过，但完整构建发现 `UIStyle` 仅提供 `operator!=`，缓存比较误用了 `==`；已修正后重新构建。构建和用户实际输入验收分别记录。
