# 独立 DComp 迁移：第一步

分支：`codex/dcomp-skin-migration`。不合并进 `shorekeeper`，不安装到日常环境。

## 这一阶段做什么

沿用官方 `82b50c9` 的 WARP、Direct2D、预乘 Alpha 交换链和 DirectComposition 窗口呈现技术，先让**已有 GDI／DirectWrite 合成的完整皮肤画布**通过新路径提交。正文、注音、九宫格、图片层、尺寸／DPI 缓存和命中坐标仍共用现有实现。

仅原生预览的 `--dcomp-test true` 会显式启用此实验路径。生产调用 `UI::Create(parent)` 保持原默认后端，不新增 UIStyle 通信字段、用户配置或常驻程序。窗口在创建时选用对应扩展样式。

失败时释放 DComp 设备资源，回到 `UpdateLayeredWindow` 提交相同画布；不重置方案、皮肤或学习数据。不声称此机制解决用户此前偶发图片消失或“问题1”。

这不是把官方完整绘制器直接合并，也不是完成 Direct2D 原生文字／图片绘制迁移。它是保留现有皮肤功能的可运行呈现基线，避免在更换窗口合成路径的同时重新实现所有布局。

## 自动验证

CI 使用独立原生预览和模拟候选，不连接日常服务、不读取用户 Rime 资料：

- 复用现有外观切换、隐藏再显示、图片加载失败回退、高亮变化和缓存像素回归。
- D2D 输出在 Present 前从 GPU／WARP 资源读回，与完整预乘 BGRA 源画布逐行比较；不同像素即判失败。
- 改变候选长度、上方／旁边／隐藏注音及整页空注音，检查重建与呈现。
- 人为注入提交失败，要求回到 GDI、生成新帧且画布像素哈希不变。
- 覆盖纯配色、守岸人三个变体及含框体素材的通用示例；完整组件、安装包和校验清单仍由独立分支 Actions 生成。

像素读回仅用于测试，会同步等待和增加开销；不作为日常呈现耗时。通过这些检查也不能替代用户多显示器、锁屏／远程会话、实际黑闪和桌面外观验收。本轮没有此类本机操作。

## 后续迁移门槛

1. 先确认新窗口合成路径、失败回退和设备重建，再分阶段把九宫格、静态图片层与文字绘制改为原生 D2D。
2. 保持格式与布局规则，共用包加载、资源 revision 和有效偏好；设备相关资源失效时保留可重建的 CPU 源素材。
3. 增加真实设备重置、DPI／屏幕边缘和装饰命中验证；测试读回不能证明系统合成后的每个屏幕像素相同。
4. 在同一输入、素材、尺寸、显示器和呈现条件下比较完整后端；不能把当前额外上传整帧的桥接阶段宣传为提速。
5. 完整适配与测试后才讨论合入日常分支；安装仍单独取得授权。
